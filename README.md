# Doubao Character Identity Card Skill

一个面向豆包的实验性角色身份卡 Skill。它接收一张或多张人物参考图，尝试生成一张固定八面板、3:4 竖版、纯白背景的角色身份卡，用于 AI 图片与短视频中的角色一致性参考。

> 重要：当前版本是“单次生成整张拼图”的提示词型方案，不是确定性排版程序。豆包底层图像工具的批量数量、局部遮罩能力和像素级布局不一定受 Skill 文本控制。请先阅读“已知缺陷”。

## 目标版式

- 左上：正面头肩大图。
- 右上 B：严格无头的正面服装与身体素材。
- 右上 C：严格无头的侧面服装与身体素材。
- 右上 D：保留完整后脑勺和背面发型的 180°背面全身。
- 底排：左 90°侧脸、左 45°、0°正脸、右 45°四个头肩角度。
- 画布：3:4 竖版、纯白背景和纯白模块缝隙，不显示 A–H 字母或面板标题。

详细坐标、提示词、验收标准和返修规则见 [`SKILL.md`](./SKILL.md)。

## 安装

1. 下载本仓库，或下载 Releases 中的 ZIP。
2. 将包含 `SKILL.md` 和 `LICENSE` 的 `doubao-character-identity-card` 文件夹或 ZIP 导入支持 Skill 的豆包环境。
3. 上传角色身份参考、服装参考等图片，并明确每张图的用途。

豆包不同版本的 Skill 导入方式和图像工具能力可能不同；以你当前客户端显示的入口为准。

## 使用示例

```text
使用 doubao-character-identity-card：参考图1的面部和发型，参考图2的服装，生成一张人物身份卡。
```

多张参考图代表不同参考用途，不代表需要输出多张结果。

## 已知缺陷与原因

### 1. 豆包可能一次显示两张相同或近似结果

**表现：** Skill 明确要求只交付一张，但界面仍同时展示两张图片。

**原因：** 生成数量可能由豆包底层图像工具或界面批量策略控制。Skill 中的“生成 1 张”属于文本指令；如果工具没有向 Skill 暴露 `n=1` 参数，图片返回后也可能被界面自动全部展示。

**当前缓解：** Skill 要求在支持数量参数时设置为 1；若后台仍返回多张，只验收并选择最好的一张作为语义上的最终结果。

**限制：** 当前缓解不能保证隐藏已经由豆包界面自动展示的额外图片。

### 2. B、C 正面和侧面身体可能自动长出头部

**表现：** B 或 C 仍出现脸、头发、耳朵、下巴或皮肤脖颈，即使提示词反复要求无头。

**原因：** 单次扩散生成倾向维持“完整人物”的视觉合理性；当服装参考图本身是完整模特时，模型还会直接复制其全身结构。负面提示词通常不足以稳定压过这种完整人物先验。

**当前缓解：** Skill 重复规定 B、C 为衣领边界遮罩后的无头素材，并将任何头部、头发、耳朵或脖颈判为验收失败，最多进行两次聚焦返修。

**限制：** 实测中，两次返修后仍可能失败。继续叠加“绝对无头”等措辞通常不会带来稳定改善。

### 3. 模块尺寸可能偏离固定网格

**表现：** 左上大图被放大到约半幅；上排过高、底排被压缩；四个底排面板宽度不一致。

**原因：** 生成模型擅长近似构图，不是像素级排版引擎。即使给出精确坐标，它仍可能按常见拼贴审美重排。

**当前缓解：** `SKILL.md` 同时提供像素坐标、百分比、禁止阈值和返修提示词。

**限制：** 这些规则提高接近标准版式的概率，但不能保证像素级一致。

### 4. 底排脸部角度可能重复

**表现：** 左侧脸、左 45°和右 45°看起来是同一方向，只改变了眼神或轻微偏转。

**原因：** 多面板单次生成会优先保持脸部相似度，导致姿态差异被压缩；“左 45°”等文字也可能被模型理解成视线方向，而不是真正的头骨旋转。

**当前缓解：** Skill 使用鼻尖方向、可见眼睛数量、远侧眼宽度、耳位和头骨偏航角定义四个角度，并将角度近似判为失败。

**限制：** 同一张拼图内同时兼顾身份一致和大幅度姿态变化仍不稳定。

### 5. A–H 字母或其他说明文字可能被画进图片

**表现：** 图片顶部出现 B、C、D，底排出现 E–H。

**原因：** 模型可能把提示词中的内部面板代号理解为需要渲染的版面标签。

**当前缓解：** Skill 明确说明 A–H 仅用于内部描述和验收，最终图片不得显示。

**限制：** 单次生成仍可能偶发渲染字母或水印。

### 6. 局部返修可能破坏已经合格的内容

**表现：** 修复 B/C 后，布局、脸部身份、服装或底排角度发生变化。

**原因：** 如果豆包使用整图重绘而非真正的局部蒙版编辑，返修会重新采样整张图片。

**当前缓解：** 返修提示词要求只修改指定面板，并限制最多两轮，避免持续消耗额度和扩大漂移。

## 推荐的可靠解决方案

如果项目要求稳定生产，不应继续依赖“一次生成整张身份卡”。推荐改为以下流水线：

1. 分别生成或选择 A–H 各面板素材。
2. B、C 可以先生成完整正面和侧面人物，再使用确定性裁切或蒙版从衣领边界移除头、头发和脖颈。
3. D 单独保留完整后脑勺和背面发型。
4. E、F、G、H 分别生成并验收左 90°、左 45°、0°、右 45°，不要在同一次拼图生成中完成。
5. 使用图像处理程序按固定坐标把八个面板合成到 1086×1448 画布。
6. 用像素级检查验证模块边界、纯白背景、可见文字和 B/C 遮罩。
7. 最终只导出并交付一张 PNG。

这套“分面板生成＋确定性合成”方案可以真正控制输出数量、模块尺寸和 B/C 无头边界；生成模型只负责人物内容，不再负责精确排版。

## 当前版本适合什么场景

适合：

- 快速制作角色参考草图；
- 能接受人工验收和返修的低频任务；
- 先验证人物造型与身份一致性。

不适合：

- 要求每次都严格像素一致的自动化生产；
- 无法接受 B/C 偶发带头的工作流；
- 需要由 Skill 强制控制豆包底层返回图片数量的场景。

## 隐私与身份边界

- 使用可识别真人作为身份锚点前，请确认拥有相应使用权限。
- 未获得授权时，只提取非识别性的脸型、发型和身材方向，生成不对应真实人物的原创角色。
- 不应声称恢复了参考图的隐藏提示词、模型、LoRA、种子或私有参数。
